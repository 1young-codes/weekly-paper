## 1. 텍스트 데이터 전처리 과정

### 한 줄 요약
원시 텍스트를 모델이 다룰 수 있는 수치 벡터로 바꾸기 위해 정제, 토큰화, 정규화, 벡터화의 단계를 거칩니다.

### 자세한 설명
전처리는 크게 네 단계로 나뉩니다.

1. **정제 (Cleaning)**: HTML 태그, URL, 특수문자, 이모지, 중복 공백 같은 노이즈를 제거합니다. 분석 목적에 맞지 않는 정보를 걷어내는 단계입니다.
2. **토큰화 (Tokenization)**: 텍스트를 의미 단위로 쪼갭니다. 영어는 공백 기준 분리가 쉽지만, 한국어는 교착어라 형태소 분석기(Mecab, Okt 등)나 서브워드 방식(BPE, WordPiece, SentencePiece)이 중요합니다.
3. **정규화 (Normalization)**: 대소문자 통일, 어간 추출(stemming) 또는 표제어 추출(lemmatization), 불용어(stopword) 제거, 맞춤법 교정 등으로 표현의 편차를 줄입니다.
4. **인코딩 / 벡터화 (Encoding / Vectorization)**: 정수 인코딩 후 One hot, BoW, TF-IDF 또는 임베딩(Word2Vec, FastText, 사전학습 임베딩)으로 수치화하고, 패딩(padding)으로 시퀀스 길이를 맞춥니다.

**면접 포인트**: 전처리 강도는 모델에 따라 달라집니다. TF-IDF 기반 전통 ML은 불용어 제거와 어간 추출이 성능에 크게 기여하지만, BERT 같은 사전학습 트랜스포머는 자체 서브워드 토크나이저를 쓰기 때문에 과한 전처리를 오히려 지양하고 원문을 최대한 살립니다.

### 예시 / 비유
요리 재료 손질에 비유할 수 있습니다. 시장에서 사온 재료(원시 텍스트)를 씻어서 흙을 털고(정제), 먹기 좋은 크기로 자르고(토큰화), 크기와 모양을 고르게 맞춘 뒤(정규화), 레시피가 인식하는 계량 단위로 환산하는(벡터화) 흐름입니다. 다만 어떤 요리(모델)냐에 따라 손질 강도가 달라진다는 점이 핵심입니다.

## 2. FastText vs Word2Vec

### 한 줄 요약
FastText는 단어를 문자 단위 n-gram(서브워드)의 합으로 표현하기 때문에, Word2Vec이 처리하지 못하는 미등록 단어(OOV)와 형태 변화를 잡아냅니다.

### 자세한 설명
- **Word2Vec**: 단어를 더 이상 쪼갤 수 없는 하나의 토큰으로 보고, 각 단어마다 벡터 하나를 학습합니다(CBOW / Skip-gram). 학습 어휘에 없던 단어(OOV)는 벡터 자체가 없어 처리하지 못하고, "apple"과 "apples"를 완전히 별개로 취급합니다.
- **FastText**: 단어를 문자 n-gram 집합으로 분해합니다. 예를 들어 "apple"은 `<ap`, `app`, `ppl`, `ple`, `le>` 같은 조각들로 나뉘고(경계 기호 `<`, `>` 포함), 단어 벡터는 이 조각 벡터들의 합으로 계산됩니다.

FastText의 장점은 세 가지입니다.

1. **OOV 대응**: 학습 때 못 본 단어라도 구성 n-gram 벡터를 조합해 표현을 만들어냅니다.
2. **형태 정보 포착**: 어근이나 접사를 공유하는 단어끼리 비슷한 벡터를 갖습니다. 형태가 풍부한 언어, 특히 한국어 같은 교착어에서 강점이 큽니다.
3. **희귀 단어 성능**: 드문 단어도 흔한 서브워드를 공유하므로 더 안정적인 표현을 얻습니다.

트레이드오프도 있습니다. 서브워드를 다루느라 저장 공간과 연산량이 늘고, 의미와 무관하게 형태만 비슷한 단어가 가깝게 묶이는 경우가 생길 수 있습니다.

### 예시 / 비유
Word2Vec은 단어를 통째로 암기한 사람입니다. 처음 보는 단어가 나오면 백지가 됩니다. FastText는 단어를 조각(어근, 접두사, 접미사)으로 쪼개 이해하는 사람이라, "unhappiness"를 처음 봐도 un + happy + ness로 뜻을 추론합니다. 레고 블록으로 단어를 조립하는 방식이라고 보면 됩니다.

## 3. Attention이 Seq2Seq에서 해결하는 문제

### 한 줄 요약
Attention은 디코더가 매 출력 시점마다 인코더의 모든 은닉 상태를 직접 참조하게 해서, 고정 길이 context vector 하나에 입력을 몰아넣으며 생기는 정보 병목과 장기 의존성 문제를 해결합니다.

### 자세한 설명
기존 RNN 기반 Seq2Seq는 인코더가 입력 문장 전체를 마지막 은닉 상태 하나, 즉 고정 크기 context vector로 압축합니다. 문장이 길어질수록 앞부분 정보가 뒤로 밀려나며 소실되는 정보 병목(bottleneck) 현상이 생기고, 긴 문장 번역에서 성능이 급격히 떨어집니다.

Attention은 이 압축을 없앱니다. 디코더가 단어를 하나 생성할 때마다,

1. 인코더의 모든 은닉 상태와의 관련성 점수(attention score)를 계산하고,
2. softmax로 가중치를 구한 뒤,
3. 가중합으로 그 시점 전용 context vector를 동적으로 만들어냅니다.

즉 "지금 이 단어를 생성하려면 입력의 어디를 봐야 하는가"를 매번 새로 학습합니다. 그 결과 정보 병목이 완화되고, 긴 시퀀스 성능이 오르며, 어텐션 가중치를 시각화하면 입력과 출력의 정렬(alignment)까지 해석할 수 있습니다.

### 예시 / 비유
통역사에 비유할 수 있습니다. 고정 context vector 방식은 긴 연설을 끝까지 들은 뒤 딱 한 문장으로 요약해 외우고 통역하는 것과 같아서, 앞 내용을 잊기 쉽습니다. Attention은 통역하는 도중 필요할 때마다 원문 스크립트의 해당 부분을 다시 들여다보는 방식입니다. 시험을 오픈북으로 보며 필요한 페이지를 그때그때 펼치는 것과 같습니다.

## 4. Transformer vs Seq2Seq(RNN 기반)의 근본적 차이

### 한 줄 요약
Transformer는 순환(recurrence) 구조를 완전히 걷어내고 오직 self-attention만으로 시퀀스를 처리해서, 순차 계산 대신 병렬 처리와 거리에 무관한 전역 의존성 포착을 가능하게 합니다.

### 자세한 설명
여기서 비교 대상인 Seq2Seq는 통상 RNN / LSTM 기반 인코더-디코더를 가리킵니다.

기존 RNN 기반 Seq2Seq는 토큰을 t=1, 2, 3 순서대로 하나씩 처리하고, 각 시점이 이전 은닉 상태에 의존합니다. 그래서 병렬화가 불가능해 학습이 느리고, 멀리 떨어진 토큰 사이의 의존성은 여러 스텝을 거쳐야 전달되어 약해집니다(gradient vanishing).

Transformer의 근본적 차이는 다음과 같습니다.

1. **순환 제거, self-attention 채택**: 모든 토큰이 모든 토큰을 한 번에 참조합니다. 토큰 간 거리와 무관하게 직접 연결되어 경로 길이가 사실상 O(1)입니다.
2. **병렬 처리**: 순차 의존이 없으므로 전체 시퀀스를 동시에 계산합니다. GPU 활용이 극대화되어 학습이 훨씬 빠릅니다.
3. **위치 정보 주입**: 순환이 사라진 대신 순서 정보도 사라지므로, positional encoding으로 위치를 명시적으로 넣어줍니다.
4. **Multi-head attention**: 여러 표현 부분공간에서 서로 다른 관계를 병렬로 포착합니다.
5. **구조**: 인코더와 디코더가 각각 self-attention 및 FFN 블록을 쌓아 올립니다. 디코더는 미래 토큰을 못 보게 하는 masked self-attention과, 인코더 출력을 참조하는 encoder-decoder attention을 함께 씁니다.

이 병렬 학습 가능성이 대규모 사전학습 모델(BERT, GPT)의 토대가 되었습니다.

### 예시 / 비유
RNN 기반 Seq2Seq는 릴레이 경주입니다. 한 주자가 다음 주자에게 바통(은닉 상태)을 순서대로 넘기는데, 뒤 주자가 첫 주자의 정보를 받으려면 여러 손을 거쳐야 하고 한 번에 한 명씩만 뛸 수 있습니다. Transformer는 원탁 회의입니다. 모든 참가자가 동시에 서로를 마주보고 누구와든 직접 대화하며, 순서가 필요하면 명찰(위치 인코딩)에 번호를 붙여 구분합니다.
